# xxd-ui-kit 优化计划（对照 Kumo 深度检查）

> 2026-10-12。前一轮计划（`docs/PLAN.md`）把底子搭好了；这一轮对照 Kumo 找差距，目标是：
> **以后用这一套能做出任何想要的东西**——组件齐、交互细、有一个专门展示小小东风格的站。
> 每个阶段开工前读这份和 `DESIGN-PRINCIPLES.md`；做完在第 8 节打勾。

---

## 0. 结论

1. **组件**：Kumo 有 54 个组件、3 个区块；我们原生层 43 个，但对上 Kumo 的只有 **约一半是完整的**，
   其余是「有但缺变体 / 状态」或「没有」。最缺的是表单进阶（密钥输入、输入组、自绘选择）、表格进阶、侧栏、复制类、工具条、区块模板。
2. **交互细节**：我们的组件「能用、对风格」，但 Kumo 在每个组件上多做了一层手感：实心按钮的材质、浮层从锚点长出来、
   toast 堆叠和滑走、复制后的小气泡、tooltip 连着出现不再等、手机上对话框变底部抽屉可下滑关闭……
   这些我们大多没有。第 3 节逐条列出，并翻译成小小东的语言（不照抄，守原则）。
3. **展示站**：Kumo 的文档站本身就是一套「呈现逻辑」——首页组件墙、每页固定结构、活演示 + 源码自动抽取、
   属性表从注册表生成、设计建议用「好 / 不好」对照、每页同时给人看和给 AI 看（.md / llms.txt）。
   我们现在只是在 Kumo 站里塞了 4 个页面。计划：**用同样的架构新建 `packages/xxd-site`**，专门呈现小小东风格（第 5 节）。
4. **React 层**：Kumo 的 React 组件已经换皮，但小小东独有的东西（dock、sheet、设置组、外观组、卡片、阅读排版……）
   只有原生版，React 里没有；Kumo 组件里还有写死的英文文案。
5. **小小东自己的业务模式**（拖放区、图片查看器、拖拽排序、按天分组的记录、登录、会员购买……）在各插件里各写各的，
   Kumo 没有，但对你最常用——值得收进来（第 4 节）。

## 3. 交互细节（Kumo 怎么做 → 我们怎么做）

每条都按原则翻译：**只动 opacity / transform、不弹跳、颜色只表意义、强调靠墨色**。标 ⚖️ 的和现有原则有冲突，需要你在第 7 节决定。

| # | 细节 | Kumo | 我们的做法 |
| --- | --- | --- | --- |
| I1 ⚖️ | **实心按钮的材质** | 渐变底 + 顶部 1px 内高光 + 比底色深 10% 的边；hover 渐变变亮；按下边变深 | 墨色 / 主色实心按钮：顶部 1px 内高光（`inset 0 1px 0` 白 12%）+ 深 8% 的边；hover 底色提亮 6%；**按下下沉 0.5px**（transform）。只用在实心按钮上，卡片和普通按钮仍然平 |
| I2 ⚖️ | hover 的颜色变化 | **立即变**（过渡会显得迟钝） | 进入立即变、离开 140ms 淡回（两边的好处都要） |
| I3 | 浮层出现 | 从锚点方向缩放（`transform-origin` 跟着方向）0.9 → 1 + 淡入 150ms | 菜单 / popover / tooltip / 下拉：从锚点方向 0.96 → 1 + 淡入 150ms，收回 100ms；对话框和 sheet 保持「升起」 |
| I4 | 键盘与鼠标高亮 | 菜单项 `data-highlighted`：键盘移动和鼠标悬停是同一个高亮 | 同：鼠标移进来就把焦点移过去，只有一个高亮，不会出现「键盘一个、鼠标一个」 |
| I5 | Tooltip 连续出现 | Provider 分组：第一次等，之后在附近按钮间移动立即出现 | 第一次 400ms；300ms 内移到下一个立即出现；可选小箭头 |
| I6 | Toast | 堆叠（叠成一摞，hover 展开）、滑动关闭、同一消息再来时「跳一下」 | 最多叠 3 张；hover / 聚焦展开；横向滑动关闭；同一句话重复时不再加一张，只轻轻上下动 2px；支持「撤销」 |
| I7 | 复制反馈 | 按钮旁冒出「Copied」小气泡并轻跳 | 图标变勾 + 旁边「已复制」小气泡淡入 1.2s（不跳，位移 2px） |
| I8 ⚖️ | 折叠展开 | 高度 + 透明度过渡 | 内容淡入 + 下移 4px；高度直接变（守「只动 opacity / transform」）。或者允许 `interpolate-size` 高度过渡——你定 |
| I9 | 加载按钮 | 转圈替换图标 | 文字保留但透明（**宽度不跳**），转圈居中；完成后图标变勾 1s 再恢复（xPoster 已有这个做法） |
| I10 | 悬停才出现的操作 | 面包屑复制、表格行操作、可复制文字：`group-hover` 显示 | 统一 `.xxd-reveal`：hover 或 focus-within 显示；触屏常显；键盘能到 |
| I11 | Tabs 溢出 | 横向滚动、可拖 | 两端渐隐遮罩 + 左右小箭头；选中项自动滚进视野 |
| I12 | 手机上的对话框 | 变底部抽屉，下滑关闭（滑得快就关） | 窄屏时 `.xxd-dialog` / `.xxd-panel` 自动变底部抽屉，顶部把手，下滑超过 1/3 或速度够快就关 |
| I13 | 侧栏折叠 | 宽度过渡 | 折叠成 56px 图标栏：切换即时，标签淡出、图标不动；悬停图标出 tooltip |
| I14 | 光标与禁用 | 所有可交互元素统一 `cursor: pointer`，禁用不响应 | 同：一条全局规则覆盖 `xxd-*` 里的可交互元素；禁用统一 0.45 透明度 + `not-allowed` |
| I15 | 焦点陷阱 | Base UI 自动 | sheet / 面板 / 抽屉补焦点陷阱（图片排序的探针 P13 就测这个）；关闭回到触发按钮 ✅ 已有 |
| I16 | 同心圆角 | 规则：外圆角 = 内圆角 + 间距 | 令牌加 `--r-inner: calc(var(--r-md) - var(--pad))` 的写法与工具类；直角模式下自然都是 0 |
| I17 | 等宽字混排 | 行内等宽字缩到 0.9em | 已有（`.xxd-code-inline` 0.92em），写进原则 |
| I18 | 图标与首行对齐 | 多行文字时图标对齐第一行 | `.xxd-icon-line` 工具类（高度 = 行高） |
| I19 | 数字变化 | — | （小小东自有）计数、额度、会员到期：等宽数字，变化时旧的上滚出、新的上滚进（xPoster 的会员行） |
| I20 | 列表重排 | — | （小小东自有）排序后元素滑到新位置（FLIP，420–660ms，图片排序已有），做成通用工具 |

## 5. 展示站 `packages/xxd-site`（同 Kumo 架构）

**为什么新建而不是继续改 Kumo 文档站**：Kumo 站里全是 Cloudflare 的内容和英文；继续往里塞会和上游冲突，
而且呈现不出「小小东风格」。用同样的架构（Astro + MDX + 活演示）新建一个，内容全是我们的，Kumo 站保留作对照。

### 架构（照 Kumo 的做法）

- Astro + MDX；每个组件页用同一套组件：`ComponentExample`（活演示 + **自动抽取的源码**）、`PropsTable`（**从 `registry.json` 生成**）、`ComponentSection`。
- 顶部固定条：**直角 / 圆角、主色、主题、密度**四个开关，全站跟着变；还有「原生 | React」切换（同一个组件两种实现并排）。
- 搜索（⌘K，用我们自己的命令面板）、右侧目录、键盘快捷键、「复制本页」。
- 每页同时出一份 `.md`；站点根目录 `llms.txt`、`/api/registry.json` —— 给 Claude / Codex 查。
- 全部静态构建，本地 `pnpm site dev`；部署只在你决定时（Cloudflare Access）。

### 内容结构

| 栏目 | 页面 |
| --- | --- |
| 首页 | 组件墙：每格一个活组件（能点能切），一句话说清这是什么；顶部四个外观开关 |
| 开始 | 三种用法（插件 / 会员站 / React）；`pnpm xxd new` 一分钟做出一个插件 |
| 原则 | 每条原则一个「好 / 不好」对照小样（像 Kumo 的设计建议，内容是我们的 12 节原则 + 第 3 节新增的） |
| 基础 | 颜色（色板 + 对比度数字 + 18 个主色在亮暗下的样子）· 圆角（直角 / 圆角并排）· 字体与层级 · 间距 · 动效（每档速度点一下就播放）· 图标（201 个，搜索，点击复制名字 / SVG / `data-xxd-icon`） |
| 组件 | 每个组件一页：活演示 · 变体 · 尺寸 · **状态矩阵**（默认 / hover / 聚焦 / 按下 / 禁用 / 加载 / 出错并排静态呈现）· 属性表 · 键盘与读屏 · 规则 · 相关组件 |
| 模式 | 第 4 节的小小东模式 + dock、sheet、设置页、外观组、文案写法 |
| 模板 | 插件侧边栏、设置页、选项页、会员站详情面板、文章阅读页、资源列表页、删除确认 —— 每个都能「复制整页 HTML」 |
| 工具 | CLI、`xxd.config.json`、sync / adopt、验证脚本、Skill |
| 更新 | 更新日志 |

### 质量门禁

- **截图回归**：每个组件页 × 4 种外观（亮 / 暗 × 直角 / 圆角），无头 Chromium 截图存基线；改组件时自动对比（像 Kumo 的 visual-regression，用我们已经跑通的 Playwright）。
- 每页零控制台错误、手机宽度不横向滚动、所有活演示键盘可用。

## 6. 原则需要补的

从 Kumo 的 15 条设计建议里，和我们一致或补充的，写进 `DESIGN-PRINCIPLES.md`：

- 相关的字靠得更近（标题和它的说明之间距离 < 和下一组之间）。
- 文字周围的垂直间距略小于水平间距（光学对齐）。
- 不改字距（不用 letter-spacing 调整中文）。
- 同心圆角（I16）。
- 行内等宽字 0.9em（I17）；图标对齐首行（I18）。
- 有阴影的浮层不再加实线边以外的边框（我们已是「一条安静的 --line」，一致）。
- 折叠时内容保持尺寸，不在动画里挤压变形。
- 对话框用 open 状态控制，不要条件渲染（否则没有开关动画）——写进 React 用法。

Kumo 那条「正文 14px」与我们不同：插件侧边栏是 13px 为主、会员站阅读 15px。保持我们的。
