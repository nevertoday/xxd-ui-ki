# 设计师对抗走查与优化计划（V 阶段）

> 2026-10-14。R1–R6 和小程序版（M1–M6）做完以后，换一个角度再挑一遍：**设计师拿它干活**时会在哪里卡住、会挑什么刺。
> 和 R 阶段不同，这次不是只读评审，而是在本机预览（:4400）的真实 Chrome 里量出来的：计算样式、文字位置、截图逐张看。
> 这份是下一轮优化的依据。开工前读这份和 `DESIGN-PRINCIPLES.md`；每批做完在第 6 节打勾写日期。第 3 节没定的，相关条目先不动。

---

## 0. 结论

1. **单个零件仍然干净**：墨色、直角、发丝线、暖黑这些气质，挑剔的人也挑不出毛病；亮暗、圆角、主色切换都不闪。
2. **设计交付这一侧缺东西**：组件页没有尺寸标注，图标只能一个个复制，小图标的线比标称的细。设计师要打开开发者工具自己量。
   （没有 Figma 库也是一条，但维护者很少用 Figma，2026-10-14 定为不做，见 D18。）
3. **同一个组件，React 版和 HTML 版长得不一样**（下面第 2 节 C 组，截图实测）。按钮字号、表头、输入框边框、标签页下划线都不同，
   React 版主按钮还默认带着渐变质感。设计师会问「设计稿该对哪一个」，开发会问「验收按哪一个」。
4. **文档说的和量出来的对不上**：令牌写「行高落在 4px 网格」，组件预览里实际有 35 种字号 / 行高组合，大多是 18.2px、16.9px 这类小数；
   原则写「4px 基准」，组件 CSS 里还有 114 处写死的间距，6 / 10 / 14 / 5px 都有。挑剔的设计师一量就会发现。
5. **模板页有几处一眼可见的细节问题**：表格同一行文字不在一条线上、同一行控件三种高度、手机上表格最后一列被裁、详情面板盖住半张卡片。

## 1. 怎么测的

六个挑剔的设计师角色，各自按自己的工作流去「用」这套东西，专找会被挑的地方：

| 角色 | 他要做的事 | 他会先挑什么 |
| --- | --- | --- |
| 产品设计师 | 用这套组件出一个插件的设计稿，交给开发 | 有没有 Figma 库、变量；稿子和代码对不对得上 |
| 品牌设计师 | 把自己的品牌色套进去 | 品牌色进去以后还是不是原色；预设色板是否讲究 |
| 视觉 / 排版 | 量像素 | 行高、间距、对齐、字号阶梯是不是真的成体系 |
| 交互 / 动效 | 写状态和动效规范 | 禁用、按下、选中、动效时长是否有令牌、是否一致 |
| 手机 / 小程序 | 出小程序设计稿 | 设计稿按多宽出、和网页版差在哪、手机上的版式 |
| 设计系统负责人 | 往里加组件、长期维护 | 规则能不能被检查、文档有没有「怎么扩展」 |

用的办法（脚本在会话的临时目录里，V2 会把它们变成 audit 项）：

- 59 个组件页的预览区，逐个元素读计算样式：字号 / 行高、字重、内边距 / 间距、控件高度、文字颜色。
- 同一个组件的 HTML 和 React 两个标签页，各截一张图并排看，并对比计算样式。
- 5 个模板 × 亮直角 / 暗圆角各截一张；资源列表页再截 390px 手机宽；首页整页；小程序演示首页。
- 读 `tokens.css`、组件 CSS、`accent.js`；18 个主色预设换算成 OKLCH 看明度和彩度。

## 2. 发现

严重度：**P0** 设计师没法正常干活或一眼看出是错的；**P1** 挑剔的人会挑、会削弱信任；**P2** 打磨。每条都标了证据。

### A. 设计工具这一侧（产品设计师、设计系统负责人）

- **A1 没有 Figma 库**（~~P0~~ 不做，见 D18）。展示站和文档里一次都没提 Figma。仓库里的 `packages/kumo-figma` 是上游 Cloudflare 的插件，
  生成的是 Kumo 原来的样子（Phosphor 图标、Cloudflare 令牌），不是小小东。
- **A2 令牌导不进设计工具**（P2，Figma 不做以后只剩「拿到算好的具体值」这一点有用）。`@xxd/tokens/dist/tokens.json` 是 CSS 变量平铺，值里还有 `var(--ink)`、`color-mix(…)`。
  它不是 W3C 设计令牌格式（DTCG），没有亮 / 暗两个 mode，也没有主色这一维。Figma Variables 和 Tokens Studio 都吃不进去。
- **A3 图标只能一个个复制**（P1）。/foundations/icons 点一个复制一个（HTML / SVG / React / 名字），没有整包 SVG 下载。
- **A4 小尺寸图标的线变细**（P1）。线宽 1.5 写在 24 网格里，会跟着图标一起缩放：16px 时约 1px，14px 时 0.875px，12px 时只有 0.75px。
  所以 12 / 14px 的图标比 16px 的看起来细、发灰。原则写的是「线宽永远是 1.5」，设计师按 1.5px 画的稿子和实际渲染对不上。
- **A5 组件页没有规格标注**（P1）。没有「结构图」（高、内边距、图标和文字间距、圆角各是哪个令牌），设计师要自己用开发者工具量。

### B. 文档说的和量出来的对不上（视觉 / 排版、交互）

- **B1 行高不在网格上**（P1）。令牌写「行高落在 4px 网格上，字号和行高成对用」，但组件 CSS 里 `--leading-*` 只用了 2 次，
  其余是 7 种无单位行高（1.35 / 1.4 / 1.45 / 1.5 / 1.55 / 1.6 / 1.8）。实测预览里有 35 种字号 / 行高组合：
  13 / 18.2、13 / 16.9、13 / 19.5、13 / 20.15、13 / 18.85、12 / 16.8、12 / 15.6、12 / 19.8、16 / 22.4……
- **B2 间距不在 4px 刻度上**（P1）。组件 CSS 里 114 处写死的 padding / gap / margin（content 21、overlay 15、structure 13、patterns 12……），
  常见值是 14px、10px、6px、5px、3px、2px。实测预览里 6px 出现 94 次、10px 25 次、14px 16 次，还有 5 / 11 / 22 / 34px。
  R5-3 只收了按钮、输入、列表、标签页这几样。
- **B3 字号阶梯太密，说明文字没有定数**（P1）。13 / 14 / 15 / 16px 四档各差 1px，设计师分不出也用不准。
  同样是「说明文字」，Field 的提示是 12px，列表行的说明是 13px，对话框正文是 12px，表格里的状态标签是 11px。
- **B4 禁用态没有令牌**（P1）。按钮和表单用 `opacity: 0.45`，另一处用 `0.55`。半透明叠在主色、暗色、图片上，结果颜色没法预测，设计稿也没法标。
- **B5 动效档位说法不一**（P2）。原则写「四档速度」，令牌里有五个（多一个 `--motion-panel: 180ms`，原则里没出现）。
- **B6 灰阶冷暖混用，有两个几乎一样的灰**（P1）。亮色的 `--line #e7e7ea`、`--line-strong #c9c9ce`、`--line-control #86868b` 偏冷（带蓝），
  `--muted-2 #9a968d` 偏暖，`--muted #6b6b6b` 是中性灰；暗色却全是暖的。`--selected-bg #ededed` 和 `--wash-strong #ececee` 肉眼分不出，
  设计师会问为什么要两个令牌。
- **B7 线宽体系外的线**（P2）。拖放区的虚线 1.5px（`patterns.css:40`），普通屏上发虚；虚线的点长由浏览器决定，Chrome 和 Safari 不一样。
- **B8 断点没有令牌**（P1）。整个组件 CSS 只有 3 个宽度断点：419px、480px、640px（419 这个数尤其像临时写的），也没有布局栅格的说明。
  设计师出响应式稿时不知道按哪几个宽度出。

### C. React 和 HTML 两套长得不一样（产品设计师，P0）

在同一页、同一外观下，切换「原生 HTML」和「React」两个标签实测：

| 组件 | HTML | React |
| --- | --- | --- |
| 按钮 | 13px；主按钮、危险按钮纯平；描边按钮的边是 `--line-strong` | 14px；**主按钮和危险按钮带渐变和内高光**（页面是 `data-finish="flat"`）；描边更浅 |
| 输入框 | 边框 `--line-control`（3:1，按 D11 改过） | 边框看起来是浅的 `--line`，D11 没落到 React |
| 表格 | 表头 12px / 500 / 灰；数字右对齐、等宽；有外框和行线 | 表头 14px / 600 / 黑；数字左对齐；没有外框、没有行线 |
| 标签页 | 13px；下划线细、只在文字下 | 14px；下划线粗、和整个标签一样宽 |
| 徽标 | 11px | 12px |
| 对话框的触发按钮 | 40px 高 | 36px 高 |

R6-9 把控件高度和内边距对齐了，但字号、颜色、质感、表格版式都还没有对齐，也没有一个对照测试来拦。

### D. 模板和页面上看得见的细节（视觉、手机）

- **D1 表格同一行文字不齐**（P1）。资源列表第一行：名称「长文发布」文字顶在 481px，同一行「最新」「2,410」在 484.5px，差 3.5px，
  名称列明显偏上（这一列有图标，用了不同的对齐）。状态列「已上架」是 11px，比同一行的 13px 小两档。
- **D2 同一行三种高度**（P1）。资源列表的筛选行：搜索框 40px，旁边「全部 / 落后 / 待发布」是 26px 的标签。
  设置页账号行的「开通会员」是 32px，其它设置行的控件是 40px。
- **D3 手机上的页面头和表格**（P1）。390px 宽：页面头的「导入 / 新建插件」按钮插在标题和说明文字中间（读的顺序变成标题 → 按钮 → 说明）；
  表格最后一列「已上架」被裁掉一半，没有能横向滑动的提示。
- **D4 详情面板盖住半张卡片**（P1）。1280px 宽的「会员站详情面板」模板：瀑布流第三列被右侧面板盖住，卡片被拦腰切开；
  面板里的大图下半截被底部 dock 裁掉，没有留白。
- **D5 开关的「开」不像开**（P1）。亮色下开关打开是 `--switch-on #56565b` 深灰，乍看像禁用；直角模式下的开关像一个方块复选框。暗色下没有这个问题。
- **D6 文章页段落和代码块贴在一起**（P2）。「令牌」那一节，段落到代码块只有约 8px，比标题前的间距小得多，代码块像挂在段落上。
- **D7 小程序首页的列表没有行线**（P1）。演示小程序首页 14 行 48px 高的行，行之间没有线，只在小标题下画了一条全宽线。
  原则第 4 条是「列表只在行之间画细线」，网页版也是这样。
- **D8 手机顶栏太挤**（P2）。展示站 390px 宽的顶栏一排 7 个控件（菜单、标志、搜索、亮 / 暗 / 跟随、主色、语言、GitHub）。

### E. 颜色（品牌设计师）

- **E1 品牌色进来就不是原色了**（P1）。选「暖橙 #d65f32」，主按钮实际是 `#c1562d`，强调文字是 `#ab4c28`；「珊瑚 #e07a5f」的主按钮变成 `#b0604b`，偏褐。
  这是为了白字对比度 ≥ 4.5，原则里写了，但设计师拿到的是「一个主色变出 action / text / fill / fill-hover，亮暗各一套，共 8 个值」，
  文档里没有一张对照表，也没有「品牌色必须原样出现」的选项。
- **E2 预设色板不讲究**（P1）。18 个预设换算成 OKLCH：明度从 0.52 到 0.69，彩度从 0.031（雾灰蓝，几乎是灰）到 0.161（暖橙、X 蓝）；
  暖橙和珊瑚色相只差 4°，琥珀和驼色色相一样（75°）；X 蓝是第三方品牌色，饱和度明显比邻居跳。
  设置页里 17 个彩色圆点没有可见的名字，只能一个个点着看。
- **E3 暗色没有「抬起」的层**（P1）。暗色下页面 `#171612`，卡片、菜单、对话框、面板都是同一个 `--paper #201f1a`；
  浮层的阴影 `rgba(0,0,0,0.42)` 在暗底上几乎看不见，层次只剩一条 `#34322b` 的线。菜单盖在卡片上时，两者同色。

### F. 缺的设计规范（设计系统负责人、手机设计师）

- **F1 小程序设计稿按多宽出**（P1）。小程序版用 px 不用 rpx，这是对的，但微信设计师习惯按 750 宽出稿。没有一句话写「按 375 宽、1 倍出稿，数值直接用」。
- **F2 没有空状态、插图的规范**（P2）。空状态只有一个图标加两行字；什么时候可以用插图、插图怎么画（线宽、配色），没有说法。
- **F3 图表的多系列配色**（P2）。单色系统画 4 条以上的线，靠线型区分（R4-8），但设计稿要用的「系列色 / 线型」令牌没有列出来。
- **F4 没有「这样做 / 别这样做」的图**（P2）。原则写得很细，但全是文字。设计师最快的学习方式是成对的对比图（比如「选中行：一层淡色 ✓ / 淡色 + 竖条 ✗」）。
- **F5 没有写给设计师的入口**（P1）。/start 是写给开发的（装包、命令行）。设计师进来不知道先看哪、令牌怎么用、出稿按什么宽度。

2026-10-14：维护者定了 D18（不做 Figma），其余交给 AI 助手按建议定。下表最后一列就是决定。

| # | 问题 | 选项 | 决定 |
| --- | --- | --- | --- |
| D18 | Figma 库 | 做 / 不做 | **不做**（维护者很少用 Figma）。`kumo-figma` 维持 D17 的「留着、只中和」。设计交付走展示站：组件规格标注、图标整包下载、模板的「复制整页 HTML」 |
| D19 | React 和 HTML 不一样时，以谁为准 | 以 HTML（`@xxd/css`）为准 / 以 React 为准 | **以 HTML 为准**。它是我们自己写的、过了对比度和原则检查；React 是 Kumo 换皮，往 HTML 看齐 |
| D20 | 字号阶梯 | 保持 9 档 / 去掉 15px，只留 11 · 12 · 13 · 14 · 16 · 20 · 24 · 28 | **去掉 15**（只有 Prose 正文和大号按钮在用，分别并到 16 和 14），每一档固定配一个 4px 网格上的行高；「说明文字」定为 12px / 20（实现时改的：12 / 16 折成两行的中文太挤） |
| D21 | 品牌色保真 | 保持自动加深 / 加一个「原样」开关：实心底用原色，白字不够 4.5 时字自动换成墨色 | **加开关（`data-accent-exact`），缺省仍是自动加深**。展示站「颜色」页加一张「一个主色 → 8 个派生值」的对照表 |
| D22 | 亮色开关「开」的颜色 | 保持深灰 `#56565b` / 改成墨色 `--ink`（有主色时是主色） | **改成墨色**。深灰在亮纸上像禁用；墨色和主按钮一致 |
| D23 | 小图标的线宽 | 跟着缩放（现在）/ 固定 1.5px（`vector-effect: non-scaling-stroke`）/ 12、14px 用单独画的粗一档版本 | **固定 1.5px**，12px 的 chevron 另行检查观感。改动小，设计稿里也好标 |
| D24 | 灰阶的冷暖 | 保持 / 亮色的线和控件边也改成暖灰，和 `--muted-2`、暗色统一 | **统一成暖灰**，彩度很低（肉眼只觉得「不冷」），改完重新跑对比度门禁 |
| D25 | 预设色板 | 保持 18 个 / 重排：等明度、色相均匀分布，去掉 X 蓝或改名「天蓝」 | **重排**，数量减到 12 个左右；去掉 X 蓝（第三方品牌色），需要的人可以自定义主色。改之前出一张新旧并排图给维护者看 |

## 4. 阶段

条目格式：编号 · 问题（严重度 · 工作量 · 对应第 2 节）→ 改法。

### V1 · 两套实现对齐（按 D19）

起因：设计稿只能对一个样子。这件事不先做，后面的规格标注会标错对象。

- **V1-1 对照测试先行**（P0 · M · C）真实浏览器里，同一组件的 HTML 和 React 各渲染一份，比较高度、内边距、字号、行高、字重、颜色、边框、圆角、阴影 / 背景图。
  先覆盖按钮、输入框、选择、复选、开关、标签页、徽标、表格、对话框、菜单，十个组件；不一样就失败。现在先跑一次，把差异列成清单（预计先红）。
- **V1-2 按钮**（P0 · S · C）React 主按钮、危险按钮去掉缺省的渐变和内高光，只在 `data-finish="material"` 下出现；字号 13px；描边按钮的边对齐 HTML。
- **V1-3 表单控件的边**（P0 · S · C）React 输入框、选择、复选、开关的边用 `--line-control`（D11 补落到 React）。
- **V1-4 表格**（P1 · M · C）React `Table` 的表头、数字列右对齐和等宽数字、外框和行线对齐 HTML 的 `.xxd-table`。
- **V1-5 标签页、徽标、对话框触发按钮**（P1 · S · C）字号、下划线（短、细、只在文字下）、高度对齐。
- **V1-6 组件页加「两种实现一致」的标记**（P2 · S）对照测试通过的组件在页面上标一下；没通过的写明差在哪，不让设计师自己发现。

验收：对照测试十个组件全绿，进 CI；展示站逐个组件切换两个标签，截图并排没有肉眼差异。

### V2 · 文档和实现对齐：行高、间距、字号、禁用、灰阶

起因：设计师按令牌出稿，开发按 CSS 实现，两边必须是同一组数字。

- **V2-1 字号和行高成对**（P1 · M · B1、B3，按 D20）每档字号定一个行高令牌（11 / 16、12 / 16、13 / 20、14 / 20、16 / 24、20 / 28、24 / 32、28 / 36），
  组件里的无单位行高全部换成令牌；多行正文（Prose、对话框正文）用单独的「阅读行高」令牌。「说明文字」统一成一个用法。
- **V2-2 间距收到刻度上**（P1 · L · B2）接着 R5-3 把剩下的 114 处收掉：能用 `--space-*` 的直接用；确实要 2px、6px 的（比如图标和文字的光学间距），
  加命名令牌（`--space-0-5`、`--gap-icon`…）并写明用途。
- **V2-3 禁用态令牌**（P1 · S · B4）`--disabled-ink`、`--disabled-bg`、`--disabled-line`（亮暗各一套），不再用 opacity；对比度门禁对禁用态不做 4.5 要求，但要和可用态明显不同。
- **V2-4 灰阶整理**（P1 · S · B6，按 D24）亮色灰阶统一冷暖；`--selected-bg` 和 `--wash-strong` 要么拉开差别，要么合成一个。
- **V2-5 动效和线宽的说法统一**（P2 · S · B5、B7）原则和令牌对齐（五档就写五档，或者把 180ms 并进去）；拖放区虚线改 1px，或者用背景画固定点长的虚线。
- **V2-6 断点令牌**（P1 · S · B8）定 3 个断点（比如 480 / 768 / 1024）写进令牌和原则，现有的 419 / 480 / 640 收进去；「间距」页加一节布局栅格。
- **V2-7 把这次的测量做成门禁**（P1 · M）audit 加三项：预览里的行高必须是行高令牌之一；内边距和间距必须在刻度上；
  同一行（同一个 flex / 表格行）里的文字基线差 ≤ 1px、控件高度只能有一种。合同测试拦新增的无单位行高和写死间距。

验收：重新跑这次的测量脚本，字号 / 行高组合 ≤ 10 种且都在表里；写死的间距只剩有令牌名的；新门禁全绿。

### V3 · 模板和页面细节

起因：模板是设计师最常拿来当起点的东西，细节问题会被原样复制。

- **V3-1 表格行对齐**（P1 · S · D1）名称列（带图标）和其它单元格文字对齐；状态标签在表格里用 12px。
- **V3-2 一行一个高度**（P1 · S · D2）筛选标签在工具行里和搜索框同高（或者搜索框用 32px 那一档）；设置行里的按钮统一高度。
- **V3-3 手机上的页面头和表格**（P1 · S · D3）窄屏时说明文字紧跟标题，操作按钮排在说明后面；表格横向可滑，并给右边缘一道渐隐提示。
- **V3-4 详情面板模板**（P1 · S · D4）面板打开时瀑布流让出位置（列数减少），不盖住卡片；大图在面板里完整显示、留出边距。
- **V3-5 开关**（P1 · S · D5，按 D22）亮色「开」改成墨色 / 主色；直角模式下的开关和复选框拉开形状差别（比如更扁的长条）。
- **V3-6 文章排版的段距**（P2 · S · D6）代码块、引用、列表前后的间距统一成段距，不贴着上一段。
- **V3-7 小程序首页列表加行线**（P1 · S · D7）和网页版一样，只在行之间画线；检查小程序其它列表（Cell 组）是不是同样的问题。
- **V3-8 手机顶栏**（P2 · S · D8）390px 宽时把亮 / 暗 / 主色 / 语言收进一个「外观」按钮。

验收：四种外观 × 1280 / 390 宽，五个模板和小程序首页截图逐张过；V2-7 的新门禁覆盖模板页。

### V4 · 颜色

- **V4-1 品牌色保真**（P1 · M · E1，按 D21）加「原样」开关；/foundations/colors 加对照表：选一个主色，列出亮暗 8 个派生值和它们各用在哪、对比度多少。
- **V4-2 预设色板重排**（P1 · S · E2，按 D25）等明度（OKLCH L 差 ≤ 0.04）、彩度相近、色相间隔均匀；色板旁边显示名字（或悬停 / 选中时显示）；X 蓝按 D25 处理。
- **V4-3 暗色的抬起层**（P1 · S · E3）加 `--paper-raised`（暗色比 `--paper` 亮一档，亮色等于 `--paper`），菜单、popover、对话框、toast 用它；暗色浮层的边换成 `--line-strong`。
  对比度门禁覆盖抬起层上的文字。

验收：18（或新数量）个预设 × 亮暗都过对比度门禁；暗色下菜单盖在卡片上截图能一眼分出层次。

### V5 · 设计交付（不做 Figma，按 D18）

起因：设计师不进 Figma，也要能在展示站上拿到准确的数字和素材。

- **V5-1 组件规格标注**（P1 · M · A5）组件页加「规格」一节：结构图，标出高、内边距、间距、圆角、字号各是哪个令牌，直角 / 圆角、标准 / 紧凑各一张。
  从真实浏览器的计算样式自动生成，不手写；构建时生成，和 CSS 不会对不上。
- **V5-2 图标整包下载**（P1 · S · A3）图标页加「下载全部 SVG」（zip，按名字命名，附中英关键词表）；单个图标可以选 12 / 14 / 16 / 18 / 20px 复制。
- **V5-3 图标线宽**（P1 · S · A4，按 D23）图标的线固定 1.5px（`vector-effect: non-scaling-stroke`），检查 12px chevron 和 20px 侧栏图标的观感；
  图标页说明这条规则；小程序版（mask 图）同样处理。
- **V5-4 算好的令牌表**（P2 · S · A2）`@xxd/tokens` 多出一份 `tokens.resolved.json`：亮 / 暗 × 直角 / 圆角的具体值（没有 `var()` / `color-mix()`），
  给规格标注、V4-1 的颜色对照表和 `llms.txt` 用；测试对一遍和 `tokens.css` 一致。

验收：挑 12 个常用组件（按钮、输入框、选择、复选、单选、开关、标签页、分段、列表行、设置组、对话框、toast），规格一节里的数字和真实渲染逐项一致（测试比对）；
下载的 SVG 包能直接拖进 Sketch / Illustrator / Keynote 用，线宽在 12–20px 下都是 1.5px。

### V6 · 写给设计师的规范

- **V6-1 「设计师从这里开始」页**（P1 · S · F5）中英两版：先看哪几页、令牌怎么用、出稿的宽度和断点、规格和图标去哪拿、和开发交接时给什么（组件名 + 外观设置，而不是截图里的像素）。
- **V6-2 小程序出稿规范**（P1 · S · F1）按 375 宽、1 倍出稿，数值直接用；胶囊按钮让位、安全区、44px 点击区的示意图。
- **V6-3 这样做 / 别这样做**（P2 · M · F4）原则第 4、5、9、10 条各配两到三对对比图（用真组件渲染，不是手画）。
- **V6-4 空状态和图表配色**（P2 · S · F2、F3）空状态什么时候只用图标、什么时候可以配图；图表的系列色、线型令牌列出来。

验收：一个没接触过这个项目的人只看 V6-1 那一页，能说出设置页的控件高度、间距、说明文字字号和亮暗颜色各是哪个令牌，并找到对应的规格和图标。
